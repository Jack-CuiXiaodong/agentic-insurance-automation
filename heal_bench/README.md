# heal_bench · 真实网页上的自愈测试

模拟平台只能证明"机制是对的"。这个工具用来回答更难的问题：
**在真实网站的真实改版面前，自愈还管不管用？**

## 它做什么

1. 打开某个页面的**旧版本**，记下目标控件（比如「登录」「查验」按钮）的指纹。
2. 打开同一个页面的**新版本**，让自愈判断"同一个控件现在是哪个"。
3. 和你标注的正确答案比对，记为：

| 结果 | 含义 | 要求 |
|---|---|---|
| ✓ 找对 | 选中的就是正确控件 | 越高越好 |
| · 停手 | 认不准，没选（真实运行时会转人工） | 可以接受 |
| ✗ 找错 | 自信地选了错误的控件 | **必须接近 0，这是最要紧的指标** |
| ! 出错 | 页面打不开、标注写错等，不计入分数 | 修正后重跑 |

## 只读保证

- **从不点击、从不提交、从不填写**，只打开页面和读取页面结构。
- 不碰验证码、不登录（需要登录才能看到的页面不在测试范围内）。
- 两次打开页面之间默认间隔 3 秒（`--delay`），像人在浏览，不像爬虫。
- 有测试守着"从不点击"这一条（`tests/test_heal_bench.py::test_benchmark_never_clicks`）。

## 怎么用

```bash
# 1. 先用示例确认工具能跑（需要先启动本地模拟平台：python legacy_app/app.py）
python -m heal_bench heal_bench/cases.example.json

# 2. 真实网站：把用例写在 heal_bench/local/ 下（这个目录被 git 忽略，不会进公开仓库）
python -m heal_bench heal_bench/local/cases.json --out heal_bench/local/report.json
# 想看浏览器在干什么就加 --headed
```

## 用例怎么写

```json
{
  "cases": [
    {
      "name": "某平台登录页 · 登录按钮",
      "intent_keywords": ["登录", "登 录"],
      "negative_keywords": ["注册", "忘记密码", "取消"],
      "baseline": {"url": "<旧版本地址>", "selector": "<旧版本上这个按钮的选择器>"},
      "versions": [
        {"label": "2022 版", "url": "<新版本地址>", "expected": "<新版本上正确按钮的选择器>"},
        {"label": "2024 版", "url": "<更新的版本地址>", "expected": "...", "wait_ms": 3000}
      ]
    }
  ]
}
```

- `selector` / `expected` 支持 Playwright 的写法：`#id`、CSS、`text=登录`、`role=button[name="登录"]`。
  在浏览器里按 F12 → 右键元素 → 复制 selector，最省事。
- `expected` 指向按钮里面的文字 `<span>` 或外面的包装层都可以，工具会自动找到对应的按钮。
- `wait_ms`：页面是前端渲染、加载慢时，额外等待的毫秒数（可以写在用例上或单个版本上）。
- `intent_keywords` / `negative_keywords`：只在不写 `baseline` 时用到（那时走关键词兜底）。

## 真实改版从哪来

**历史版本（推荐先做）**：互联网档案馆保存了很多公开页面多年的版本。地址格式：

```
https://web.archive.org/web/<年月日时分秒>id_/<原网址>
```

注意中间的 **`id_`**：它返回原始页面，不加档案馆的工具栏、不改写表单地址。
不加 `id_` 的话，表单提交地址会被改写成档案馆的地址，指纹里的"提交地址"一项会失真。
前端渲染很重的页面（单页应用）在存档里经常跑不起来，优先选服务端渲染的页面，
比如各类登录页、查询页的首页。

**线上版本**：把同一个线上地址每隔一段时间（比如每周）作为一个新版本加进用例，
平台一改版，立刻能看到自愈跟不跟得上。

## 结果发回来时

把终端输出（或 `--out` 的 JSON 报告）发给我。特别留意这几类备注，它们指向需要改进的地方：

- **「正确控件在 iframe 里」**：当前自愈只看主页面，这是已知缺口。
- **「正确控件不在候选列表里」**：它不是按钮/链接（比如一个可点击的 `<div>`），
  或者当时不可见——说明候选采集规则需要扩展。
- **任何「找错」**：最优先排查。

## 不要放进公开仓库的东西

真实网站的地址、选择器、报告都放在 `heal_bench/local/`。公开仓库里只有工具本身和
示例用例，项目"全合成数据、不含任何真实机构标识"的底线不变。
